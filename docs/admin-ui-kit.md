# UI-kit рабочих кабинетов MyStore

Образец — `/platform/admin`. Платформа и магазины используют одну WorkspaceShell. Профиль обозначает аккаунт; выбранный контекст определяет меню и полномочия.

## Основа

- Корневой класс `admin-kit-shell` задаёт цвета: тёмно-зелёное меню `--admin-dark`, светлый фон `--admin-canvas`, белая поверхность `--admin-surface`, зелёный акцент `--admin-accent` и границы `--admin-border`.
- Компоненты `AdminBrand`, `AdminIdentity`, `AdminCard`, `AdminMetric`, `AdminStatus` и `AdminEmpty` находятся в `apps/web/src/platform/AdminKit.tsx`. Используйте их вместо отдельной копии бренда, профиля или карточки показателя.
- Общая оболочка находится в `apps/web/src/layout/WorkspaceShell.tsx`. Новые рабочие страницы используют её вместо собственной копии меню и верхней панели. Общие классы `admin-kit-sidebar`, `admin-kit-topbar`, `admin-kit-content` задаёт оболочка. Существующие seller-классы сохраняют поведение прокрутки и печати.
- Новые стили рабочих страниц ограничивайте `admin-kit-shell` или классом компонента; публичная витрина имеет собственный UI-kit.

## Разметка

- Для нескольких карточек и формы приглашения используйте `page-stack`: между самостоятельными блоками 22 px. Внутри форм — 16 px между элементами, подпись отделена от поля.
- Заголовок страницы и действия могут переноситься. Длинные email и названия не должны расширять всю страницу.
- Таблицы находятся внутри `table-wrap`; на узком экране прокручивается таблица, а не страница целиком. Кнопки и выпадающие списки остаются доступны.
- Для checkbox используйте `checkbox-label`: поле 18 × 18 px рядом с подписью, а не поле шириной 100% над текстом.
- Кнопки главного действия имеют класс `primary`; группы действий используют `actions` с переносом. Не ставьте независимые кнопки вплотную.
- Статусы загрузки, ошибки и успешного действия показывайте явно. Не представляйте отсутствие данных при ошибке запроса как ноль.

## Переходы и роли

- Между страницами одного кабинета используйте React Router. Из кабинета на публичную витрину Next.js используйте обычный `a href`, чтобы сервер обслужил актуальный интерфейс.
- Контексты и меню определены в `workspace-navigation.ts`. «Платформа» доступна администратору, магазины — только по membership из `/api/auth/me`. «Мои магазины» доступны при нескольких магазинах; сводки запрашиваются только для собственных.
- `/seller` — точка входа по роли: admin → платформа, owner/manager единственного магазина → товары, cashier → касса. `/seller?view=shops` открывает выбор нескольких магазинов. Весь интерфейс остаётся в одной оболочке.
- Раздел платформы хранится в URL (`section=overview|applications|products|audit`), поэтому обновление и назад/вперёд сохраняют выбор. У активного пункта `aria-current="page"`; hover имеет другое оформление.
- Название пункта меню соответствует действию. Для не-владельца история называется «Продажи», возвраты оформляет владелец. Не создавайте ссылки между дубликатами оболочки и не переименовывайте профиль аккаунта при смене контекста.
- Проверка прав остаётся в API. Скрытие кнопки не выдаёт и не отменяет полномочия. Возвраты оформляет владелец; кассир работает с продажами и своими сменами.
- Создание товара отправляет карточку на проверку. Подсказка не обещает автоматическую публикацию до одобрения платформой.

## Адаптивность и проверка

Проверяйте 360, 768, 1024 и 1440 px. На телефоне доступны выход и выбор магазина при нескольких доступных магазинах. На компьютере меню и содержимое магазина прокручиваются независимо; панель партнёра также имеет отдельные области прокрутки. Печать этикеток сохраняет отдельные print-стили.

После изменений запускайте Prettier, typecheck, build и тесты. Регрессии входа, контекстов и истории URL закреплены в `apps/web/e2e/workspace-navigation.spec.ts`. Регрессии отступов, checkbox и перехода на витрину закреплены в `apps/web/e2e/admin-consistency.spec.ts` и `storefront-navigation.spec.ts`.
