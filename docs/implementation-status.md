# Результат первого этапа

Реализовано серверное ядро: сессии сотрудников, права магазина, варианты, поиск по штрихкоду, приход, остатки и атомарная товарная продажа. UI и публичный маркетплейс в этот этап не входят.

## Проверки

40 интеграционных тестов прошли на PostgreSQL 18.4. Пройдены сборка TypeScript, typecheck и форматирование. Сквозной HTTP-сценарий на чистой базе подтвердил приход 10 → продажа 2 → остаток 8; миграции и seed запущены повторно без дублей. Документированная команда dev проверена по HTTP после исправления компиляции метаданных.

Независимое ревью выявило три существенных дефекта: UUID-варианты разного регистра, UUID-магазины разного регистра в блокировках идемпотентности и отсутствие decorator metadata при запуске dev через tsx. Два дефекта UUID воспроизведены падающими тестами, исправлены нормализацией; вся suite после исправления зелёная. Dev переведён на tsc watch с node watch и проверен сквозным HTTP-сценарием.

Добавлена проверка отката после записи первой строки и ошибки второй. CI собирает Docker image и выполняет контейнерный HTTP smoke. Docker недоступен в локальном окружении, поэтому результат контейнерной проверки подтверждается отдельно статусом GitHub Actions.

## Решения реализации

- Работа ведётся в новом отдельном checkout и ветке feat/inventory-core; исходные документы main не изменяются.
- Из-за отсутствия Docker локальные транзакционные тесты выполнялись на отдельной временной PostgreSQL; поставляемое окружение использует Compose.
- Количество ограничено 1 миллиардом единиц, деньги — безопасным целым числом JavaScript. Более крупные значения отклоняются, чтобы не терять точность.
- Первый этап проводит внутреннюю товарную продажу без смен, платежей и фискализации. Использовать его как коммерческую ККМ до следующих этапов нельзя.
- UUID приводятся к нижнему регистру до проверки дублей и отпечатка операции; блокировка магазина использует тот же канонический вид.
- Развитие UI, сканера, печати, заказов, outbox, модерации, публичного каталога, архивирования, индивидуальных разрешений и эксплуатационных SLA сохранено для следующих этапов. Это не скрытые реализации первого этапа.
- Восстановление неизвестного результата пока выполняется повтором исходного запроса с тем же ключом. Отдельный GET статуса операции не требуется контрактом этого этапа.

Замечание о сложных паролях Compose исправлено отдельным DATABASE_URL_CONTAINER с URL-кодированными реквизитами. Отложенных мелких замечаний ревью к этому этапу не осталось. Полноценное коммерческое использование требует следующих модулей и проверки реального оборудования.
