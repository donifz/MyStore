# Витрины и партнёры

## Покупатель

Главная / открывает каталог товаров. /shops показывает магазины. Поиск работает по названию товара и магазина, внутри витрины — по её товарам. Есть категории, сортировка по цене, фильтр наличия и страницы результатов. Карточка показывает описание, цену в сомах и доступное количество; «Связаться с магазином» открывает звонок. Онлайн-заказ пока не оформляется.

Количество берётся из stock_balances: physical − reserved. Приход, кассовая продажа и возврат меняют ту же запись. Открытая страница обновляется каждые 30 секунд и при возвращении в окно; окончательное наличие уточните у продавца. Себестоимость, резерв отдельно и документы в публичный API не попадают.

## Партнёр

В футере выберите «Стать партнёром». Введите название магазина, email и пароль не короче 12 символов. Создаётся один скрытый магазин и аккаунт владельца. Регистрация не заменяет пароль существующего email и не выдаёт сессию автоматически. После успешного сообщения перейдите во вход и используйте сохранённый пароль.

В кабинете выберите «Витрина», укажите описание, город, телефон для покупателей, адрес и часы работы. Телефон и город обязательны для публикации. Эти контакты станут доступны всем покупателям. Включите «Опубликовать магазин» и сохраните. Появится ссылка «Открыть витрину». Адрес постоянный, имя магазина задаётся при регистрации.

В существующем каталоге нажмите название товара. Можно менять цену, описание, категорию и «Показывать на витрине». Штрихкод остаётся тем же. Владелец и менеджер редактируют карточки; настройки витрины доступны только владельцу. Новая карточка разрешена к публикации автоматически, но видна только при опубликованном магазине. При создании товара количество остаётся нулевым до приёмки.

Снятие публикации магазина скрывает весь каталог немедленно для следующих запросов. Скрытая карточка возвращает публичный 404. Старые проведённые продажи сохраняют свои цены.

## API

- GET /public/products?q=&category=&store=&inStock=false&sort=name&page=1&pageSize=24
- GET /public/stores?q=&page=1&pageSize=24
- GET /public/stores/:slug
- GET /public/stores/:slug/products/:id
- POST /partners/register: email, password, shopName; требуется разрешённый Origin.
- GET/PUT /shops/:shopId/storefront: владелец; PUT принимает description, city, address, phone, hours, published.
- PUT /shops/:shopId/variants/:id: каталог; name, salePriceMinor, description, category, published.

Публичный pageSize максимум 100, page максимум 1000000; sort: name, price-asc, price-desc. Ответы с наличием не кешируются. Изменяющие запросы кабинета с cookie требуют Origin/CSRF, как касса. Регистрация ограничена 20 запросами за минуту на адрес подключения; на одном сервере за прокси ограничения могут быть общими для клиентов.

## Границы

Нет email/SMS-подтверждения, модерации, фото, собственной доставки, корзины, онлайн-платежей, онлайн-заказов, пользовательских доменов и печати. Не принимайте регистрацию за проверку продавца. Данные рабочей витрины публикует её владелец; автоматических демонстрационных товаров в production нет.

## Next.js и поисковые системы

Публичные страницы обслуживает Next.js App Router (`apps/storefront`). Каталог, витрина и карточка товара содержат название, цену и наличие уже в серверном HTML. Кабинет продавца остаётся React/Vite; API и база прежние. Всё запускается в одном процессе на одном Render-сервисе.

Добавлены title/description, canonical, OpenGraph, robots.txt и sitemap.xml со всеми опубликованными магазинами. Карточки имеют Product/Offer JSON-LD с валютой KGS. Фильтры и страницы пагинации исключены из индекса как дубликаты. У скрытых товаров/магазинов HTTP404. Наличие читается без кеширования; открытая страница обновляется каждые30 секунд и при возвращении в окно.

Фильтры отправляются кнопкой «Найти» и работают без JavaScript. HTML не содержит себестоимости или токенов. Next-скрипты разрешаются уникальным nonce в CSP; произвольные inline-скрипты запрещены. `RENDER_EXTERNAL_URL` задаёт публичный адрес для canonical/sitemap; API для SSR вызывается через loopback на `PORT`. Никаких новых секретов не требуется.

Проверка SSR после production build: `node scripts/storefront-ssr-test.cjs`. Сервер запускается прежней командой; в Docker включён Next build. Сам Next dev на3000 предназначен для разработки при работающем API на3001.
