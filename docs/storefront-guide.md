# Витрины, партнёры и модерация

## Покупатель

`/` показывает общий каталог разных магазинов, `/shops` — магазины, `/shops/:slug` — витрину одного партнёра. Название, описание, категория и фото публичного товара берутся из последней одобренной версии. Цена и доступный остаток берутся из рабочего учёта. Товар без одобрения или со снятой публикацией возвращает 404. Онлайн-заказ резервирует общий остаток на 30 минут; продавец подтверждает выдачу в кабинете. Оплата на сайте и фискальный чек пока не подключены.

## Заявка партнёра

В футере выберите «Стать партнёром». Укажите магазин, email, телефон, город, адрес, категорию бизнеса и согласие. Пароль на этой странице не вводится. После отправки заявку проверяет администратор платформы. Администратор вручную связывается с вами и передаёт ссылку активации при одобрении. Ссылка одноразовая, действует 7 дней. По ней задайте пароль от 12 символов и затем войдите в `/seller/login`.

Одобрение создаёт скрытый магазин. Владелец заполняет описание, контакты и часы в «Витрина», затем включает публикацию магазина. Товар можно вести в учёте и кассе сразу, но покупателям он показывается после одобрения карточки. Если название, категория или описание меняются, старая одобренная версия остаётся видимой до следующего решения. Цена и наличие меняются сразу. При отказе продавец видит причину и может исправить карточку.

## Кабинет администратора

Пользователь с серверной ролью `platform_admin` входит по обычной форме и открывает `/platform/admin`. Там он просматривает заявки, берёт их в работу, одобряет или отклоняет с причиной; ссылка активации показывается только в ответе на одобрение. Администратор сверяет предложенную и текущую публичную карточки, одобряет либо отклоняет изменения, просматривает журнал решений. Магазин и публичная карточка не активируются самим фактом подачи заявки.

Роль назначают только серверной командой `set-platform-admin grant user@example.com --confirm=user@example.com` с `DATABASE_URL`, никогда через публичный API. Первого администратора назначают после создания доверенной учётной записи.

## API

- `POST /partners/applications` — заявка с полями `shopName,email,phone,city,address,category,agreed`, разрешённый `Origin`.
- `POST /partners/invitations/activate` — одноразовый `token,password`, разрешённый `Origin`.
- `GET /platform/admin/applications`, `GET /platform/admin/applications/:id`, `POST /platform/admin/applications/:id/decision` — только администратор.
- `GET /platform/admin/products`, `GET /platform/admin/products/revisions/:id`, `POST /platform/admin/products/revisions/:id/decision`, `GET /platform/admin/audit` — только администратор.
- `GET /public/products`, `GET /public/stores`, `GET /public/stores/:slug/products/:id` — одобренный каталог.
- `GET/PUT /shops/:shopId/storefront`, `POST/PUT /shops/:shopId/variants` — кабинет магазина.

Изменяющие запросы с cookie требуют `Origin` и CSRF; заявка и активация ограничены по частоте. Публичный API не отдаёт себестоимость, аудит и пароли. У сервиса нет автоматической отправки email/SMS: приглашение администратор доставляет вручную.

## Развёртывание

Публичные страницы обслуживает Next.js App Router (`apps/storefront`), рабочий и административный кабинеты — React/Vite (`apps/web`) и API NestJS в одном Render-сервисе. Миграция создаёт запись одобренной версии для опубликованных до внедрения товаров, сохраняя их на витрине. `RENDER_EXTERNAL_URL` задаёт canonical и sitemap. Миграцию и количество видимых карточек следует проверить на резервной копии базы перед обновлением production.
