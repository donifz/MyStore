# Второй этап: кабинет продавца и касса

Ветка feat/seller-pos. Реализованы cookie-вход/CSRF, выбор магазина, каталог, создание карточки, приёмка и касса с HID-сканированием, черновики, атомарная оплата, смены, история и возвраты. Старый API первого этапа сохраняется.

## Проверки реализации

- 57 серверных интеграционных тестов на отдельной PostgreSQL18.4: включая прежние40, доступ, CSRF, конкурентные смены, продажи, закрытие, частичный возврат и откат при ошибке платежа.
- 23 теста веб-клиента: вход, права, денежный ввод, очередь сканов, изоляция и сохранение черновиков, повреждение хранилища, ошибки quota и повтор неизвестного результата.
- Три сценария Playwright на собранном вебе и API: полный цикл продавца с потерянным ответом, восстановлением, возвратом/закрытием; доступ кассира и ширины360/768/1440; одновременная отправка одного черновика из двух окон с разными способами оплаты.
- typecheck, production build и форматирование.
- Прежний HTTP smoke выполняется против собранного приложения; контейнерная версия, включая браузерные проверки, прошла GitHub Actions.

## Условия тестового окружения

Docker локально отсутствует; используется временная выделенная PostgreSQL. Штатная загрузка Playwright Chromium недоступна, поэтому локальный браузер запускается через явный E2E_BROWSER_PATH. Из-за особенностей single-process Chromium тесты запускались отдельными командами. В CI используется штатный Chromium и отдельная mystore_browser_test внутри production image.

## Принятые уточнения

ShiftView дополнен четырьмя итогами оплаты/возвратов по способу. Владелец получает активную смену через дополнительный owner-only маршрут; кассиру остаётся маркер занятости без чужих денег. Неподтверждённый запрос сохраняет URL вместе с ключом и телом, чтобы закрытие смены можно было повторить после её фактического закрытия.

## Результат независимого ревью

Четыре важных замечания воспроизведены тестами и исправлены: атомарная фиксация запроса между вкладками, точное отображение восстановленной оплаты/возврата, повтор потерянного ответа открытия уже открытой смены, детали собственной продажи для кассира. Web Locks сериализуют запись черновика; ключ привязан к его версии, неподтверждённый URL/тело неизменны, отметка завершения блокирует устаревшее окно. Браузер без Web Locks/HTTPS блокируется безопасно. Незначительных отложенных замечаний нет.

## Границы результата

Нет выбранной/проверенной физической модели сканера, печати, фото, фискальной интеграции, обработки банковских платежей, публичной витрины и онлайн-заказов. Работа требует сети. Брак регистрируется в возврате, но не попадает в доступный остаток; его последующая складская обработка отложена. Денежная выплата отдельно после товарного возврата в этом этапе не реализована. Ограничение одной кассы сохраняется.
