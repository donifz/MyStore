# Подтверждение номера покупателя через Telegram

Эта интеграция **не является SMS OTP**. Покупатель должен открыть Telegram-бота и нажать кнопку **«Поделиться своим номером»**. Сервер сверяет `contact.user_id` с отправителем сообщения и сверяет номер с зарегистрированным номером +996. Обычная авторизация Telegram без собственного контакта **не подтверждает номер телефона**.

## Защита от случайного запуска

До настройки интеграции в production всё отключено. Регистрация и вход по телефону/паролю продолжают работать независимо от бота. В production требуется явное включение через переменные:

- `TELEGRAM_VERIFY_ENABLED=true`
- `TELEGRAM_BOT_USERNAME` — username своего бота без @
- `TELEGRAM_BOT_TOKEN` — секретный токен BotFather (хранить только в Railway)
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка 16–256 символов из `A-Z a-z 0-9 _ -`

Сначала настройте бот и вебхук, проверьте на тестовом пользователе, **только затем** включайте переменные. Не отправляйте секреты в GitHub, сообщения или логи.

Webhook URL: `https://<ваш-подтверждённый-домен>/api/integrations/telegram/buyer-webhook`.
Метод Telegram Bot API: `setWebhook`. Передайте `url` и `secret_token`, равный `TELEGRAM_WEBHOOK_SECRET`. Telegram будет присылать секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`. Обрабатываются только приватные сообщения.

## Сценарий покупателя

1. Покупатель входит в `/buyer`.
2. Запрашивает ссылку — одноразовый challenge сроком 10 минут, сохранён **только SHA-256 хеш**.
3. Переходит по ссылке `https://t.me/<bot>?start=<token>`.
4. Нажимает кнопку отправки **своего контакта** (не вводит номер текстом).
5. Сервер проверяет Telegram sender ID, номер +996, ссылку, срок, уже использованные и чужие Telegram аккаунты.
6. Только после этого устанавливаются `phone_verified_at` и `telegram_user_id`.

Повторные запросы challenge для одного аккаунта ограничены интервалом 30 секунд. Нельзя автоматически связывать покупки чужих магазинов или восстанавливать пароль только по совпадению номера. Для восстановления пароля нужен отдельный проверенный процесс.

## Выпуск

- Запустите CI и E2E с тестовой PostgreSQL.
- Настройте вебхук на отдельном боте.
- Проверьте совпадающий номер, чужой контакт, просроченный токен, повторный challenge и отказ в доступе без CSRF.
- Проверьте домен и HTTPS. Не включайте кредиты для всех покупателей одновременно.
- Проверьте резервные копии до релиза, если PR содержит миграцию.

Кредитные продажи и погашения продолжают управляться **своими отдельными флагами**. Telegram-подтверждение не включает кредит и не выдаёт лимит автоматически.
