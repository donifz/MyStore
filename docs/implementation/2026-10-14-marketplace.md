# Storefront MyStore: реализация по визуальным референсам

## Реализовано

- Главная: общий поиск товаров/магазинов, город, категории, баннер с реальными фотографиями, магазины, фильтры цены/категории/наличия, сортировка, карточки с корзиной и избранным.
- Магазины: поиск, город, район, категория, адрес, количество опубликованных товаров; единое оформление обложек и монограммы для магазинов без логотипа.
- Магазин: оформление, контакты, часы работы, способы получения, поиск и фильтры собственного каталога. Сохраняется URL `/shops/:slug`.
- Товар: увеличение опубликованной фотографии, описание, сведения о товаре, фактический доступный остаток, продавец, количество, покупка, похожие товары.
- Корзина: группы по продавцам, количества и суммы, получение для каждого магазина, общий ввод контактов. Подтверждение создаёт отдельные заказы существующим API. Частичный успех сохраняется; неизвестный результат повторяется с исходным ключом и телом. Между вкладками отправку координирует Web Locks; неподдерживаемый браузер получает объяснение, запрос не отправляется.
- Избранное хранится локально, отображает заново загруженные опубликованные товары.

## Backend и данные

Миграция `Marketplace1760000000014`: район, самовывоз, доставка в shops. Самовывоз включён по умолчанию; доставка включается владельцем в настройках витрины. API проверяет доступность выбранного способа перед новым резервированием; восстановление уже существующего заказа работает независимо от новых настроек.

Публичный API расширен фильтрами города/района/категории/цены, справочником городов/категорий и счётчиками товаров. Источник карточек — существующие product_publications, цен — variants, наличия — stock_balances (physical минус reserved). Новых дублирующих товаров или остатков нет. Склад, POS и выдача заказа используют прежние транзакционные операции.

Стоимость доставки согласуется с продавцом и не включается вымышленным тарифом в сумму заказа. Карта оставлена на будущий этап, как указано в ТЗ. Бренды, несколько фото, скидки, технические атрибуты, отзывы и рейтинги не заведены в текущем каталоге: интерфейс не изображает эти данные реальными. Общая авторизация использует существующий вход в кабинет; отдельного аккаунта покупателя нет.

## Проверки

По прямому указанию пользователя автоматические тесты для редизайна не запускались. TypeScript и production build проверяются отдельно; результаты сборки не означают прохождения сценарных тестов. Перед production потребуется применить миграцию штатной процедурой деплоя.
