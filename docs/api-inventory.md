# API товарного учёта

Base URL локально: `http://localhost:3001`. Все маршруты магазинов требуют `Authorization: Bearer <token>`. JSON тела проходят проверку типов; неизвестные поля отклоняются. shopId и variantId — UUID. Пользователь не задаёт actorId: он определяется сессией.

## Вход

`POST /auth/login`

```json
{ "email": "owner@example.test", "password": "ваш пароль" }
```

Возвращает `token` и `expiresIn: 43200`. `POST /auth/logout` отзывает текущую сессию. Не храните токен в журнале, URL или исходниках. Для будущего веб-клиента потребуется согласовать защиту хранения сессии от XSS.

## Магазин

`GET /shops/:shopId/access?permission=read` возвращает роль. Допустимые permission: read, receive, sell, catalog. Владелец и менеджер обладают всеми четырьмя правами; кассир — read и sell. Настройка индивидуальных разрешений будет отдельно.

## Создание варианта

`POST /shops/:shopId/variants`

```json
{ "name": "Рюкзак", "barcode": "0012345678905", "salePriceMinor": 15000 }
```

Barcode можно не передавать — создаётся внутренний Code 128-совместимый строковый код. Создание карточки не делает приход. Цена 0 разрешена. Barcode — 1–64 печатных ASCII-символа без пробелов; заводские коды хранятся без числового преобразования.

`GET /shops/:shopId/variants/by-barcode?code=0012345678905` и `GET /shops/:shopId/variants/:variantId` возвращают id, name, barcode, salePriceMinor.

## Приёмка

`POST /shops/:shopId/receivings` с заголовком `Idempotency-Key: <новый UUID>`.

```json
{
  "lines": [
    {
      "variantId": "UUID созданного варианта",
      "quantity": 10,
      "unitCostMinor": 10000
    }
  ]
}
```

Возвращает id документа, kind=receiving и totalMinor. В этом примере стоимость прихода — 100000 тыйын. Начальный и последующий приход используют один API. В одном документе нельзя повторять variantId; интерфейс должен суммировать отдельные сканирования в одну строку до отправки.

## Остаток

`GET /shops/:shopId/stock/:variantId`

После приведённой приёмки ответ владельцу:

```json
{ "physical": 10, "reserved": 0, "available": 10, "stockValueMinor": 100000 }
```

Кассиру возвращаются только physical, reserved и available. Нулевой остаток существует логически сразу после создания варианта.

## Продажа

`POST /shops/:shopId/sales` с заголовком `Idempotency-Key: <новый UUID>`.

```json
{
  "lines": [
    {
      "variantId": "UUID созданного варианта",
      "quantity": 2,
      "expectedUnitPriceMinor": 15000
    }
  ]
}
```

Возвращает id документа, kind=sale и totalMinor=30000. После операции physical=8, available=8, stockValueMinor=80000. Закупочная стоимость не возвращается в ответе продажи.

Если фактическая цена отличается от expectedUnitPriceMinor, ответ 409 включает currentUnitPriceMinor. Клиент показывает обновлённую цену и получает подтверждение пользователя, затем отправляет новую операцию с новым ключом.

Перед продажей блокируется баланс. Зарезервированный товар расходовать нельзя. Стоимость списания вычисляется из точной стоимости запаса пропорционально количеству и округляется до тыйына методом half-up. Оставшаяся стоимость остаётся у запаса; последняя единица списывает остаток стоимости полностью. Историческая себестоимость сохраняется в sale_lines и не меняется при новых приходах.

## Повторы и ошибки

При сетевом сбое повторите точно тот же запрос с прежним Idempotency-Key. Если первый запрос успел завершиться, вернётся первоначальный результат; новый документ не создаётся. Ключи уникальны в пределах магазина и общие для разных типов документов. Повтор ключа с другим телом или типом операции даёт 409. Перестановка строк документа не меняет его смысл и отпечаток; дубли строк запрещены.

- 400: некорректные данные, пустой документ, отсутствующий ключ, дубли, переполнение суммы.
- 401: нет сессии, срок истёк или сессия отозвана.
- 403: нет доступа к магазину или операции.
- 404: вариант отсутствует в указанном магазине.
- 409: код занят, ключ конфликтует, цена изменилась или товара недостаточно.
- 429: превышен лимит входа.

Произвольные 5xx не следует считать успешной операцией. Не отправляйте новый ключ автоматически после неизвестного результата. Лимит тела JSON задаётся Express; большие документы разделяются пользователем до отправки. Максимум — 100 строк одного документа.
