# Доступ платформы к закрытым данным магазина

Основание: часть 2 release scope. Владелец подтвердил, что полномочие выдаёт владелец магазина конкретному администратору платформы. Администратор не выдаёт его себе.

## Граница

Общий обзор платформы содержит количество магазинов/заявок/товаров на модерации и список магазинов с публичными реквизитами. Он не читает и не возвращает продажи, себестоимость, остатки, смены или контакты владельцев. Модерация продолжает работать без финансового доступа.

Владелец в отдельном разделе «Доступ платформы» указывает email существующего администратора, цель (1–500 символов) и срок 1–168 часов. Просматривает историю полномочий и отзывает доступ. Владелец с ролью администратора не выдаёт полномочие самому себе; собственный магазин доступен ему через обычный кабинет владельца. Менеджер/кассир, включая сотрудника с финансовым разрешением, не управляет полномочиями платформы.

Администратор видит список выданных ему полномочий и явно открывает финансовую сводку одного разрешённого магазина. Перед чтением показываются цель и срок. Доступ только на чтение: существующая агрегированная финансовая сводка (включая себестоимость и стоимость остатка); CSV, контакты покупателей, исходные документы, управление магазином и сменами не входят.

## API и данные

Миграция 1760000000019: `platform_financial_grants` с UUID, shop_id, admin_user_id, granted_by, purpose, created_at, expires_at, revoked_at/revoked_by. История не удаляется при отзыве. Несколько отдельных полномочий допустимы; повтор одного ключа не создаёт нового.

- GET/POST `/shops/:shopId/platform-access`: список/выдача владельцем; POST `{adminEmail,purpose,durationHours}` и UUID Idempotency-Key.
- POST `/shops/:shopId/platform-access/:id/revoke`: отзыв владельцем с UUID Idempotency-Key.
- GET `/platform/admin/financial-access`: только полномочия текущего администратора, без финансовых данных.
- GET `/platform/admin/financial-access/:id/summary`: текущая финансовая сводка по конкретному действующему полномочию; каждый успешный запрос отдельно аудируется.

Выдача, отзыв и аудит атомарны и идемпотентны. Финансовое чтение, проверка текущей роли администратора/срока/отзыва и запись аудита происходят в одной транзакции; ошибка аудита не возвращает данные. Порядок блокировок: магазин → администратор → полномочие. После ожидания блокировки срок проверяется по текущему времени БД, а не времени начала транзакции. Чтение, успевшее взять блокировку до отзыва, завершается до отзыва; следующий запрос запрещён. Аудит содержит идентификатор полномочия, магазин, автора и цель, без копирования финансовых сумм.

## Приёмка

Отказ обычному администратору без полномочия, другому администратору, другому магазину, после истечения/отзыва/снятия роли; независимость роли сотрудника и платформы; защита от самовыдачи; повторные/конкурентные запросы; rollback аудита. Общий обзор не содержит закрытых данных даже при наличии отдельных полномочий. Интерфейс сохраняет введённое при ошибке и прежний ключ при неизвестном результате, обновляет состояние с сервера.
