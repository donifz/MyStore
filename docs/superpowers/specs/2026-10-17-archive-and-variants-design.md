# Спецификация: Архив и варианты товаров (Часть 4)

Дата: 17 октября 2026 года.
Статус: Проект согласован для реализации.
Основание: [docs/implementation/2026-10-17-release-scope.md](../../implementation/2026-10-17-release-scope.md) (Часть 4).

## 1. Цели и границы

1. **Безопасное архивирование (`archived`)**:
   - Позиция каталога может быть отправлена в архив, если по ней нет активных резервов (`stock_balances.reserved = 0`).
   - При наличии хотя бы одного зарезервированного товара (`reserved > 0`) архивация отклоняется с `409 Conflict` и сообщением «Нельзя архивировать товар с активным резервом».
   - Архивация и разархивация — действия с обязательной проверкой прав (владелец или уполномоченный сотрудник магазина с правом управления каталогом; кассир не имеет права архивировать/разархивировать).
   - Действия фиксируются в `audit_log` (`action: 'archived'` и `action: 'unarchived'`, `entity_type: 'variant'`).

2. **Защита торговых сценариев при архивации**:
   - **Касса (POS / Sales)**: при попытке добавить архивированный товар в чек возвращается ошибка `409 Conflict` («Товар находится в архиве»).
   - **Приход (Receiving)**: при попытке оприходовать архивированный товар возвращается `409 Conflict` («Нельзя оприходовать архивный товар»).
   - **Публичная витрина (Storefront)**: архивный товар скрыт из каталога, поиска и категорий (`WHERE NOT v.archived`).
   - **Онлайн-заказы (Orders)**: при попытке оформить заказ на архивный товар возвращается ошибка `409 Conflict`.
   - **История и возвраты (Returns)**: ранее проданный товар из архива **можно вернуть** по исходному чеку. Возврат использует снимок строки продажи (`sale_lines`), не требует разархивации и не блокируется.

3. **Связанные варианты товара (Product Group & Variants)**:
   - В таблице `variants` добавляется `parent_id uuid REFERENCES variants(id) ON DELETE SET NULL`.
   - Если `parent_id IS NULL`, позиция является корневой (самостоятельный товар или главный вариант группы).
   - Если `parent_id IS NOT NULL`, позиция является связанным вариантом корневого товара (например, другой размер или цвет).
   - **Инвариант независимости**: каждый вариант сохраняет свой собственный `id`, штрихкод `barcode`, артикул `sku`, цену продажи `sale_price_minor`, остатки в `stock_balances` и партионную себестоимость в `stock_documents`/`stock_movements`. Никакие остатки и деньги вариантов не объединяются и не усредняются.
   - **Перенос**: существующая позиция может стать вариантом или родителем группы без изменения её первичного ключа `id` и без искажения финансовых отчётов.
   - **Витрина**:
     - В API публичного товара (`/api/public/stores/:slug/products/:id`) возвращается список доступных вариантов группы `variants: [{ id, name, size, color, salePriceMinor, available, sku }]`.
     - На странице товара покупатель видит селектор размера/цвета/варианта и выбирает вариант перед нажатием «Купить».
     - При переключении варианта цена, доступный остаток и артикул динамически обновляются.

## 2. Схема базы данных (Миграция 1760000000021)

```sql
ALTER TABLE variants
  ADD COLUMN IF NOT EXISTS archived boolean NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS parent_id uuid REFERENCES variants(id) ON DELETE SET NULL;

CREATE INDEX IF NOT EXISTS variants_shop_archived_idx ON variants(shop_id, archived);
CREATE INDEX IF NOT EXISTS variants_parent_id_idx ON variants(parent_id);
```

## 3. Права и безопасность

- Только роли `owner` и `manager` магазина имеют доступ к `PUT /shops/:shopId/variants/:id/archive` и `PUT /shops/:shopId/variants/:id/unarchive`.
- Кассир (`cashier`) получает `403 Forbidden`.
- Чужой магазин получает `403 Forbidden`.
- Попытка архивации с `reserved > 0` возвращает `409 Conflict`.

## 4. План приёмочных испытаний

1. **Архивирование и резервы**:
   - Создать товар, сделать приход 5 шт., создать онлайн-заказ (резерв = 1).
   - Попытаться архивировать -> 409 Conflict.
   - Отменить заказ (резерв = 0) -> архивация успешна (200), в audit_log записано `archived`.
2. **Торговые ограничения архива**:
   - Кассовая продажа архивного товара -> 409 Conflict.
   - Оприходование архивного товара -> 409 Conflict.
   - Публичный каталог и поиск -> архивный товар не отображается.
   - Оформление онлайн-заказа на архивный товар -> 409 Conflict.
3. **Сохранение возвратов**:
   - Продать товар до архивации.
   - Архивировать товар.
   - Оформить возврат по чеку -> возврат успешно проводится, деньги возвращаются, остаток возвращается на склад.
4. **Варианты**:
   - Создать корневой товар и добавить связанный вариант с другим размером, штрихкодом и ценой.
   - Проверить, что каждый вариант имеет свой независимый остаток и цену.
   - Проверить, что в публичном API возвращается список вариантов группы, и покупатель может выбрать и купить конкретный вариант.
