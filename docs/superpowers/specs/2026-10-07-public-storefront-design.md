# Публичные витрины MyStore — этап 3

Покупатель открывает главную с каталогом товаров и магазинов; рабочий кабинет доступен по /seller. Реализация использует действующие React/Nest/PostgreSQL и один сервис Render. Изменение учёта отражается при следующем запросе витрины; открытая вкладка обновляет наличие каждые 30 секунд и при возвращении в окно. Передача цены или себестоимости из закрытого API в публичный запрещена.

## Публикация

У магазина постоянный автоматически созданный slug, описание, город, адрес, телефон и часы работы. По умолчанию магазин скрыт. Только владелец меняет профиль и публикацию; публиковать можно после заполнения города и телефона. Все новые товары по умолчанию разрешены для витрины, но видны только в опубликованном магазине. Менеджер/владелец редактирует название, цену, описание, категорию и переключатель видимости товара. Штрихкод сохраняется неизменным. Скрытые карточки и магазины возвращают публичный 404.

## Каталог

Главная /: поиск по названию товара и магазина, фильтр категории, только наличие, сортировка по названию или цене, пагинация (24, максимум 100). /shops: список опубликованных магазинов. /shops/:slug: профиль и каталог магазина. /shops/:slug/products/:id: карточка с описанием, категорией, ценой в сомах, фактическим доступным количеством, контактами и ссылкой в магазин. Нет товара — корректное пустое состояние; отсутствующая карточка — 404 в API и понятный экран в браузере. Суммы — целые тыйыны. Доступно = physical − reserved, без дублирования складской модели. Публичные ответы содержат только явно выбранные поля; не содержат себестоимость, пользователей, суммы кассы, документы или резерв отдельно. Cache-Control: no-store для актуального наличия.

## Партнёры

Футер содержит «Стать партнёром» и «Войти для продавцов». /partner регистрирует email, пароль минимум 12 символов и название магазина. Транзакция создаёт пользователя, скрытый магазин и owner membership. Email приводится к нижнему регистру; повторный email даёт безопасный 409 без сброса пароля. Регистрация ограничена по частоте, проверяет Origin и не выдаёт сессию автоматически: после успеха пользователь входит обычным способом. Пароль хранится только как scrypt hash, не в Web Storage. Регистрация не предоставляет доступ к чужим магазинам. Публикация самостоятельная; модерация платформой пока отсутствует.

## Границы и проверка

В этом этапе нет корзины, онлайн-заказа/резервирования, SMS, банковской оплаты, загрузки фото, доменов или печати. UI сообщает, что покупка согласуется с магазином по телефону. Не создаём вымышленные товары/магазины на рабочей базе. Миграция сохраняет существующий учёт; рабочий MyStore остаётся скрытым до решения его владельца.

Интеграционные тесты: регистрация/повторы/откат, изоляция, роли, скрытые данные, фильтры/пагинация, stock после приходов/продаж, скрытие, постоянные ссылки, Origin и ограничение запросов. UI и Playwright: покупатель без входа, регистрация→вход→настройки→публикация→публичная карточка, пустые/ошибочные состояния, мобильная ширина. Перед merge — build/typecheck/format/full suite/CI и независимое ревью, после — live проверка публичных GET и прежнего входа.
