# MyStore storefront: UI-kit и шаблоны страниц

Дата: 2026-10-12
Репозиторий: donifz/MyStore
Область изменений: apps/storefront
Статус: дизайн согласован в чате; письменная спецификация подготовлена для проверки.

## Цель

Создать единый UI-kit, переиспользуемые компоненты и адаптивные шаблоны существующих страниц storefront. Зафиксировать правила в apps/storefront/AGENTS.md, чтобы следующие изменения развивали ту же систему.

Пользователь выбрал светлый интерфейс с зелёным акцентом и подтвердил предложенный состав компонентов и страниц. Результат — работающие компоненты Next.js/React, встроенные в витрину, руководство и страница /ui-kit.

## Текущий проект

apps/storefront использует Next.js App Router, React и TypeScript.
app/layout.tsx импортирует ../../web/src/styles.css, поэтому оформление публичного магазина зависит от кабинета продавца.
Catalog.tsx объединяет загрузку данных, фильтры и разметку карточек.
Checkout.tsx и BuyButton.tsx содержат существующую логику корзины, оформления, восстановления результата заказа и подтверждения замены корзины.
Существующие API-типы Product и Store находятся в lib/public-api.ts.

## Подход и границы

Использовать собственные CSS-токены и небольшие React-компоненты без новой UI-библиотеки. Альтернативы: сторонняя библиотека добавит зависимость и потребует адаптации; только обновление CSS не обеспечит повторное использование компонентов. Выбран первый подход.

Серверные страницы продолжают загружать данные и создавать metadata. Презентационные компоненты получают данные через props. Интерактивные компоненты остаются клиентскими только там, где нужны состояние и обработчики.

Новый storefront CSS не зависит от web/src/styles.css. Изменения кабинета продавца и API не входят в задачу. Не менять цены, остатки, работу корзины, ключи оформления, восстановление заказа, маршруты и SEO.

Цвета:

- border: #D9E2DC
- primary: #176854
- primary-hover: #12513F
- primary-soft: #E8F2EC
- danger: #A82E2E
- danger-soft: #FFF0F0

Типографика: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif; существующий Inter использовать только если он доступен. Не добавлять зависимость от загрузки внешнего шрифта.
Основной текст: 16 px, line-height 1.5; подписи 14 px; заголовки страниц адаптивные от 28 до 48 px.

Шкала отступов: 4, 8, 12, 16, 24, 32, 48, 64 px.
Радиусы: поля 8 px, карточки 12 px, крупные блоки 20 px.
Ширина контента: не более 1280 px, боковые поля 16 px на телефоне, 24 px на планшете, 32 px на большом экране.
Размер кликабельных контролов: не менее 44 px. Обводка фокуса — 2 px primary с отступом 3 px.

Сетка товаров: 2 колонки до 768 px, 3 колонки от 768 px, 4 колонки от 1100 px.
При ширине 320 px сетка и текст не создают горизонтального скролла. Фото имеют фиксированное соотношение сторон 1:1, object-fit: contain; отсутствие фото показывает нейтральную заглушку.
Микроанимации ограничены hover/focus, учитывают prefers-reduced-motion.

## Структура

- styles/tokens.css: именованные CSS custom properties с префиксом --sf-.
- styles/storefront.css: базовые стили, компоненты и адаптивные шаблоны с префиксом sf-.
- components/ui/: Button, LinkButton, Input, Select, Textarea, Checkbox, Badge, Alert, EmptyState, Skeleton и barrel index.ts.
- components/storefront/: Header, Footer, ProductCard, StoreCard, CatalogFilters, Price, StockBadge.
- Существующий Pagination привести к общей системе, сохранить параметры поиска.
- app/ui-kit/page.tsx и демонстрационный клиентский компонент: каталог примеров без обращения к API.
- docs/ui-kit.md: правила, интерфейсы компонентов и примеры использования.
- AGENTS.md внутри apps/storefront: обязательные правила для будущей работы.

Существующие бизнес-компоненты могут сохранять свои пути. Не создавать универсальную систему тем, сложные polymorphic/asChild API, Storybook или дополнительные библиотеки иконок.

## Контракты компонентов

Button принимает native button props, variant primary/secondary/ghost/danger, size sm/md/lg и loading. По умолчанию type=button; submit задаётся явно. loading блокирует повторное нажатие, сохраняет доступное имя и устанавливает aria-busy.
LinkButton принимает Next Link props и только применимые атрибуты ссылки, использует те же варианты оформления. Навигацию не реализовывать через onClick кнопки.

Input, Select и Textarea принимают native props, обязательный id и label, необязательные hint и error. Подсказка и ошибка связаны с полем через aria-describedby, ошибка устанавливает aria-invalid. Select принимает option children.
Checkbox использует native input type=checkbox, видимую подпись и native checked/defaultChecked/onChange.
Badge имеет варианты neutral/success/warning/danger; цвет сопровождается текстом.
Alert имеет variant info/success/error и children: error использует role=alert, сообщения о результате role=status.
EmptyState принимает title, description и необязательное действие; действие передаётся готовым ReactNode.
Skeleton декоративный, aria-hidden; контейнер загрузки отдельно предоставляет доступное сообщение.

ProductCard получает существующий Product. Ссылка ведёт на /shops/{slug}/products/{id}; вложенные кнопки и ссылки внутри общей ссылки недопустимы.
StoreCard получает существующий Store, ссылка ведёт на /shops/{slug}.
Price получает minor и использует существующий formatSom. Не хранить денежные значения в новых единицах.
StockBadge получает available, показывает наличие текстом; не изобретает статус «мало осталось».
CatalogFilters получает существующие значения фильтра и список категорий, сохраняет GET-форму, имена полей и поддерживаемые значения сортировки.
Header включает бренд, товары, магазины и существующий CartLink. Footer содержит подключение партнёра и вход продавца.

## Шаблоны страниц

Каталог /: шапка, светло-зелёный hero, поиск и фильтры, число найденных товаров, сетка карточек, пагинация. Фильтры на телефоне складываются в вертикальную форму.
Магазины /shops: заголовок, поиск, адаптивная сетка StoreCard и пагинация.
Магазин /shops/[slug]: информация магазина, доступные контакты, адрес и часы работы, каталог с теми же фильтрами и карточками.
Товар /shops/[slug]/products/[id]: возврат в магазин, фото и информация в двух колонках на desktop и одной на телефоне; цена, наличие, существующий BuyButton и карточка контактов. При отсутствии телефона не создавать нерабочую tel-ссылку.
Корзина /cart: товары и итог слева, форма справа на desktop; один столбец на телефоне. Сохранить ограничения одного магазина, блокировку при неизвестном результате и восстановление заказа.
Партнёр /partner и активация: информационный блок и форма, единые поля и состояния отправки; существующие запросы и валидация сохраняются.
404, ошибки API, пустые результаты и загрузка используют общие состояния.

Декоративный hero использует CSS/встроенную графику, не требует генерации маркетинговых фото. Примеры UI-kit явно обозначены как демонстрационные и не создают реальные заказы.

## Демонстрационная страница /ui-kit

Содержит палитру, типографику, шкалу отступов, кнопки, поля, статусы, карточки товара и магазина, пустые и загрузочные состояния, компактные примеры компоновки каталога и корзины.
Показывает hover/focus/disabled/loading/error через интерактивные примеры и краткие инструкции.
Данные локальные и фиксированные; никакой сетевой зависимости или записи в корзину.
Страница имеет noindex metadata и не включается в sitemap. В основном меню ссылка на UI-kit не добавляется.

## Правила будущей работы

Все новые элементы storefront используют токены --sf-* и существующие компоненты.
Не добавлять произвольные цвета, радиусы и отступы вне токенов без обновления руководства.
При повторении разметки выделять предметный компонент; не усложнять API ради одного применения.
Обязательны состояния normal, focus, disabled, loading и error там, где они применимы.
Контролы имеют подписи, ссылки настоящие href, формы корректные type/label, статусы объявляются assistive technology.
Серверные компоненты остаются серверными; use client добавляется только при необходимости.
Финансовая и складская логика остаётся в существующих слоях.
Учитывать корневой AGENTS.md; локальные инструкции дополняют его.

Готовность: шаблоны используют общий UI-kit, styles.css кабинета больше не импортируется витриной, правила сохранены, проверки выполнены или ограничения явно указаны.
