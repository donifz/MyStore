# Спецификация: отчёты по каналам, даты выдачи и управление платформой

Дата: 17 октября 2026 года.
Ветка: `feat/reports-and-platform-management`.
Связанная задача: Часть 6 дорожной карты релиза ([2026-10-17-release-scope.md](../../implementation/2026-10-17-release-scope.md)).

## 1. Контекст и бизнес-цели

1. **Корректный период онлайн-продаж**:
   - Онлайн-заказ создаётся покупателем в один момент (создание брони), но фактическая продажа, списание выручки и переход права собственности происходят только в момент выдачи покупателю в магазине (`status = 'issued'`).
   - В финансовых отчётах онлайн-продажа должна относиться к периоду фактической выдачи (`issued_at`), а не к дате оформления заказа (`created_at`).
   - Возвраты фиксируются датой возврата чека.

2. **Разделение выручки по каналам**:
   - Продавец должен видеть разделение выручки:
     - Офлайн-касса магазина (POS)
     - Онлайн-заказы маркетплейса (Online)
   - Возможность фильтрации отчётов по произвольному календарному диапазону (`from` / `to`).

3. **Блокировка витрины и ручные подписки**:
   - Администратор платформы может заблокировать магазин на маркетплейсе (например, при нарушении правил или неоплате) с указанием причины.
   - При блокировке витрины:
     - Магазин и его товары скрываются из публичного каталога и поиска маркетплейса.
     - Оформление новых онлайн-заказов блокируется.
     - **Касса (POS) остаётся полностью работоспособной**: продавец может открывать смены и обслуживать розничных покупателей в торговой точке.
     - Продавец сохраняет доступ в рабочий кабинет для просмотра старых заказов, остатков и экспорта документов.
   - Подписка учитывается вручную администратором платформы без автосписаний: фиксация срока действия (`subscription_until`), отображение статуса и предупреждений.

## 2. Схема данных и миграции

Миграция `1760000000023-ReportsAndPlatformManagement.ts`:
1. `online_orders`:
   - `issued_at timestamptz NULL`
   - Заполнение для исторических данных: `UPDATE online_orders SET issued_at = updated_at WHERE status = 'issued' AND issued_at IS NULL;`
   - Индекс: `online_orders(shop_id, issued_at)`.
2. `shops`:
   - `marketplace_blocked boolean NOT NULL DEFAULT false`
   - `marketplace_block_reason varchar(255) NULL`
   - `subscription_until timestamptz NULL`
   - Индекс: `shops(marketplace_blocked)`.

## 3. Серверная логика (API)

1. `OrdersService.issue`:
   - При установке `status = 'issued'` проставляется `issued_at = now()`.
2. `OrdersService.createOrder`:
   - Проверка `shop.marketplace_blocked`: если магазин заблокирован, отклоняется с `403 Forbidden` («Приём онлайн-заказов временно приостановлен»).
3. `StorefrontService`:
   - Скрытие магазинов и товаров с `marketplace_blocked = true` из публичных списков и поиска.
4. `ReportsService`:
   - `summary`:
     - Поддержка метрик по каналам:
       - `posSalesMinor`, `posSalesCount`
       - `onlineSalesMinor`, `onlineSalesCount`
     - Выданные заказы `issued_orders` фильтруются по `COALESCE(issued_at, updated_at) >= $2 AND COALESCE(issued_at, updated_at) < $3`.
   - `export`:
     - В `sales.csv` добавляется колонка `channel` (`pos` / `online`).
     - В `orders.csv` добавляется колонка `issued_at`.
5. `PlatformAdminService`:
   - `setSubscription(adminId, shopId, until)`: обновление даты подписки с записью в аудит.
   - `setMarketplaceBlocked(adminId, shopId, blocked, reason)`: блокировка/разблокировка витрины с причиной и записью в аудит.
   - `overview()`: выдача `marketplace_blocked`, `marketplace_block_reason`, `subscription_until` в списке магазинов.

## 4. Пользовательский интерфейс

1. `apps/web/src/reports/ReportsPage.tsx`:
   - Контролы выбора диапазона дат (`от` и `до`) с кнопками применения и сброса.
   - Раздельные карточки каналов продаж: POS (касса) и Online (маркетплейс).
2. `apps/web/src/platform/AdminPage.tsx`:
   - Таблица магазинов отображает статус витрины (Активна / Заблокирована) и срок подписки.
   - Действия: блокировка витрины с указанием причины, разблокировка, продление/установка подписки.
