# Проверка Gmail API и очереди внутри MyStore

Дата: 2026-10-13. Ветка: codex/gmail-inline-email. Дополнение к уже влитому PR #25 с сотрудниками и восстановлением доступа.

## Проверено локально

- Полный `npm test`: 180 API-тестов и 43 web-теста прошли. Прежний web-тест ввода закупочной цены один раз упал при нагруженном запуске, полный повтор прошёл без изменения кода.
- Typecheck и build всех трёх workspace, format:check и git diff --check прошли.
- Production Playwright: 19 сценариев прошли при первом запуске; три сценария приглашений упали из-за ошибочно заданного локального ключа шифрования. После исправления конфигурации preview все три прошли. Всего проверены 22 сценария. Витрина не изменена этой адаптацией; её 18 сценариев ранее прошли в базовой версии.

- Gmail transport: OAuth refresh и кеш access token, MIME/base64url, стабильный Message-ID, обработка ошибочных ответов без раскрытия секретов. Google endpoints заменены ответами тестового HTTP boundary; реальные письма не отправлялись.
- Очередь внутри API: сериализация ticks, расширение событий, обработка текущего письма при остановке и сохранение следующего в pending.
- Собранный API-процесс с EMAIL_PROVIDER=gmail и EMAIL_WORKER_MODE=inline принимает HTTP-приглашение, отправляет его через тестовую границу Google, записывает sent и очищает секретный payload. SIGTERM завершает процесс с кодом 0 без отдельного worker.
- Регрессионный тест сначала воспроизвёл отказ очистки transport при ошибке DB во время stop. Исправление закрывает transport в finally. Общая остановка продолжает закрывать HTTP/storefront/DB после ошибки предыдущего ресурса и возвращает код 1.
- Независимое повторное ревью не нашло новых P1/P2 замечаний после исправления остановки.

## Подключение аккаунта

Реальный Gmail OAuth и доставка не проверены: Google Cloud client и refresh token ещё не предоставлены, разрешение отправки аккаунтом не выдано. Секреты Render не менялись, платные сервисы не создавались. Порядок подключения описан в docs/gmail-setup.md. Когда Free Render спит, очередь возобновляется после пробуждения.

CI после публикации PR не ожидается по инструкции пользователя. Слияние и deployment этой адаптации не выполняются.
