# Отчёт о проверке: Доступ платформы к закрытым финансовым данным магазина

Дата проверки: 17 октября 2026 года.
Ветка: `feat/platform-financial-access`.
Среда: Node.js 24.19.0, PostgreSQL 18.

## Объём поставки

Реализована Часть 2 из [docs/implementation/2026-10-17-release-scope.md](../implementation/2026-10-17-release-scope.md):

1. **Защита общего обзора платформы** (`apps/api/src/platform/platform-admin.service.ts`, `apps/web/src/platform/AdminPage.tsx`):
   - Из общего обзора (`/api/platform/admin/overview`) удалены все закрытые показатели отдельных магазинов (выручка за день, 7-дневный график продаж, топ-5 категорий с выручкой, остатки в штуках, статусы смен, email владельцев).
   - Обзор возвращает только агрегированное число магазинов/заявок/товаров на проверке и публичные реквизиты (название, город, статус публикации).
   - Модерация партнёров и товаров работает независимо, без доступа к финансовым данным.

2. **Модель временных полномочий** (`apps/api/src/migrations/1760000000019-PlatformFinancialAccess.ts`, `financial-access.service.ts`):
   - Таблица `platform_financial_grants`: UUID, shop_id, admin_user_id, granted_by, purpose (1–500 символов), created_at, expires_at (1–168 часов), revoked_at/revoked_by.
   - Полномочие выдаёт только владелец магазина (`role = 'owner'`) конкретному администратору платформы; администратор не может выдать полномочие самому себе.
   - Запрет самовыдачи: владелец с ролью администратора платформы не может выдать доступ себе к собственному магазину (для этого используется обычный кабинет владельца).
   - Идемпотентность: запросы на выдачу и отзыв защищены `idempotency-key` и выполняются транзакционно.

3. **Аудируемое read-only чтение сводки** (`financial-access.controller.ts`, `financial-access.service.ts`):
   - Эндпоинт `GET /api/platform/admin/financial-access`: отдаёт администратору только список выданных ему полномочий (без финансовых данных).
   - Эндпоинт `GET /api/platform/admin/financial-access/:id/summary`: отдаёт финансовую сводку конкретного магазина при наличии действующего (не отозванного и не просроченного) полномочия.
   - Атомарность: проверка полномочия, текущей роли администратора, чтение сводки и запись в `audit_log` происходят в единой транзакции с блокировкой. При сбое аудита сводка не возвращается.
   - Каждый успешный запрос аудируется (`platform-access:read`), фиксируя ID полномочия, магазин, автора и цель.

4. **Интерфейс владельца и администратора** (`PlatformAccessPage.tsx`, `AdminPage.tsx`, `workspace-navigation.ts`):
   - В кабинете владельца добавлен раздел «Доступ платформы» (`/seller/:shopId/platform-access`): форма выдачи (email, цель, срок в часах), таблица истории полномочий, кнопка отзыва действующего доступа.
   - В кабинете администратора платформы добавлен раздел «Финансовый доступ» (`/platform/admin?section=financial-access`): список доступных полномочий, просмотр цели и срока, кнопка открытия сводки, панель с индикацией аудируемого режима чтения.
