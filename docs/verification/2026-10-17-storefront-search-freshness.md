# Отчёт о проверке: поиск по артикулу, сортировка по новизне и актуальность витрины

Дата: 17 октября 2026 года.
Ветка: `feat/storefront-search-and-freshness`.
Связанная задача: Часть 3 дорожной карты релиза ([2026-10-17-release-scope.md](../implementation/2026-10-17-release-scope.md)).

## 1. Объём реализации

1. **Поиск по артикулу (SKU)**:
   - В `StorefrontService.products` добавлен поиск по `v.sku ILIKE $1` наряду с `p.name`, `s.name` и `v.barcode`.
   - В публичный DTO товара (`Product`) добавлено поле `sku`, безопасное для покупателей (не раскрывает себестоимость, остатки или неодобренные карточки).
   - В карточке товара (`/shops/[slug]/products/[id]`) в блоке характеристик отображается артикул (`Артикул: {v.sku}`).
   - В шапке витрины (`Header.tsx`) и в фильтрах каталога (`CatalogFilters.tsx`) обновлены понятные подсказки: «Поиск по названию, артикулу или магазину…».

2. **Сортировка по новизне с детерминированным вторым ключом**:
   - Параметр `sort=newest` поддержан в валидации контроллера (`@IsIn(['name', 'price-asc', 'price-desc', 'newest'])`) и парсере параметров витрины `query()`.
   - Сортировка выполняется по `p.approved_at DESC, v.id ASC`. Наличие строго детерминированного второго ключа `v.id ASC` гарантирует, что при совпадении даты одобрения/публикации пагинация никогда не потеряет и не продублирует товары.
   - В выпадающий список сортировки добавлен пункт «Сначала новые».

3. **Актуальность наличия (5 секунд)**:
   - В `Refresh.tsx` интервал фонового опроса витрины уменьшен с 30 секунд до 5 секунд (`5000ms`), что строго удовлетворяет требованию обновления в пределах 5 секунд при исправной сети.

4. **Миграция и производительность**:
   - `apps/api/src/migrations/1760000000020-StorefrontSearch.ts`:
     - Добавлен индекс `product_publications_approved_at_idx` на `(approved_at DESC, variant_id)`.
     - Добавлен индекс `variants_sku_idx` на `variants(sku)`.
     - Добавлена колонка `variants.created_at timestamptz NOT NULL DEFAULT now()` и индекс `variants_created_at_idx`.

5. **Дизайн и эргономика**:
   - В фильтры добавлена кнопка «Сбросить», появляющаяся при наличии активных фильтров.
   - Минимальная высота интерактивных элементов ≥ 44 px, адаптированная сетка фильтров на экранах от 320 до 1440 px без переполнения.

## 2. Результаты испытаний

1. **Интеграционные тесты API (`storefront.e2e-spec.ts`)**:
   - Проверка поиска по артикулу: `GET /public/products?q=<sku>` возвращает ровно искомый товар.
   - Проверка сортировки по новизне: `GET /public/products?sort=newest` возвращает товары в хронологическом порядке одобрения.
   - Проверка защиты внутренних данных: себестоимость и непубличные данные не попадают в ответ.
   - Результат: 5/5 тестов успешно пройдены.

2. **Серверный SSR тест (`scripts/storefront-ssr-test.cjs`)**:
   - Проверка нормализации параметров и передачи `sort=newest` и `q=<sku>` в API.
   - Проверка отсутствия падений при невалидных фильтрах.
   - Результат: пройден.

3. **Браузерные Playwright тесты витрины (`apps/storefront/e2e`)**:
   - Проверка адаптивности на ширинах 320, 390, 768 и 1440 px без горизонтального переполнения.
   - Проверка сохранения параметров фильтрации при пагинации.
   - Проверка доступности контролов для клавиатурных пользователей.
   - Результат: 18/18 тестов успешно пройдены.

4. **Полный регрессионный прогон (`npm test`)**:
   - 39 API тестовых сьютов (231 тест) — успешно.
   - 21 Web тестовый сьют (83 теста) — успешно.
   - `npm run typecheck` — без ошибок во всех воркспейсах.
   - `npm run format:check` — все файлы соответствуют стилю Prettier.
