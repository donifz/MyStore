# Проверка индивидуальных разрешений сотрудников

Дата: 17 октября 2026 года. Ветка: `feat/staff-permissions`.
Среда: Node.js 24.19.0, PostgreSQL 18.6; отдельные базы с суффиксом `_test`.

## Реализовано

- Владелец выдаёт и отзывает `canReturn` и `canViewReports` у принятого менеджера или кассира своего магазина через раздел «Сотрудники».
- Оба дополнительных разрешения по умолчанию выключены. Владелец всегда имеет полный доступ. Смена роли сбрасывает дополнительные разрешения.
- Изменение прав и аудит `staff:permissions` с before/after атомарны. Повтор запроса не дублирует аудит и не восстанавливает уже отозванные права.
- Возвраты открывают историю продаж магазина без себестоимости. Денежный возврат требует собственной открытой смены; суммы, историческая стоимость и выплаты используют существующий учёт.
- Финансовое разрешение открывает отчёт, CSV и историю продаж; кассиру разрешает просмотр стоимости остатка. Оно не разрешает возвраты, изменение товаров или управление сотрудниками.
- API проверяет актуальные права при каждом запросе. Для возврата проверка повторяется внутри транзакции до чтения сохранённого результата операции или проведения нового документа, с блокировкой магазина перед сменой и остатками.
- Интерфейс не разрешает следующее изменение до успешного обновления списка с сервера. При сбое обновления остаётся блокировка и кнопка «Обновить список». Неизвестный результат повторяется с прежними URL, телом и ключом.

## Регрессии и ревью

До реализации новые API-тесты падали из-за отсутствующего endpoint; новые UI-тесты — из-за отсутствующих флажков и доступа по дополнительным разрешениям.

Отдельное ревью выявило две гонки: обход транзакционной проверки при повторе завершённого возврата и повторную выдачу первого разрешения из устаревшего состояния при изменении второго флажка. Обе воспроизведены падающими тестами, исправлены и повторно проверены. Повторное ревью существенных замечаний не обнаружило.

Адресные проверки после исправлений:

- API: `staff-permissions.e2e-spec.ts` и `returns.e2e-spec.ts` — 12 passed. Покрыты изоляция, независимость прав, отзыв в действующей сессии, гонка отзыва с новым возвратом и повтором завершённого, конкурентный повтор возврата, суммы/стоимость/количество документов, аудит и rollback, миграция down/up с сохранением сотрудников.

## Развёртывание и границы

Перед запуском нового API применить миграцию `StaffPermissions1760000000018` штатной командой `npm run migration:run --workspace apps/api`. Она добавляет только два boolean-поля в memberships, не меняет роли, остатки и документы. Откат удаляет дополнительные разрешения; их значения при последующем повторном применении не восстанавливаются.

Сотрудник обновляет страницу, чтобы меню учло выданные или отозванные права; API применяет отзыв без повторного входа. Уже проведённый возврат остаётся проведённым даже при отказе в повторном запросе после отзыва.

Это завершение подчасти индивидуальных прав сотрудников. Отдельное полномочие платформы на закрытые данные продавца, изменения расчётов отчётности и остальные части release scope сюда не входят.
