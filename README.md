# MyStore

Маркетплейс с общим каталогом продавцов, товарным учётом и кассой. В этой ветке реализован первый этап: серверное ядро доступа, вариантов товаров, приёмки и продаж. Публичный магазин и экран кассира будут следующими этапами.

## Что уже работает

- Вход сотрудников, сессии на 12 часов и выход с отзывом сессии.
- Разграничение владельца, менеджера и кассира внутри магазина.
- Создание варианта, генерация внутреннего кода и поиск по заводскому штрихкоду без потери ведущих нулей.
- Приёмка с закупочной стоимостью, остатки и журнал движений.
- Продажа с проверкой текущей цены, наличия и резерва.
- Идемпотентность документов, защита последней единицы от двух продаж.
- Снимки цены и себестоимости продажи, средневзвешенная стоимость запаса.

Все суммы — целые тыйыны: 15000 означает 150 сом. Количество — целое число от 1 до 1 000 000 000. Документ содержит от 1 до 100 уникальных вариантов.

## Локальный запуск

Нужны Node.js 24.15 или новее в ветке 24.x и Docker Compose. Команды выполняются из корня.

```bash
cp .env.example .env
```

В `.env` задайте случайный `SESSION_SECRET` длиной минимум 32 символа. Для генерации:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Пример пароля PostgreSQL предназначен только для локальной разработки. Если меняете его, обновите также `DATABASE_URL`, `DATABASE_URL_CONTAINER` и `TEST_DATABASE_URL`; в URL используйте URL-кодирование специальных символов.

```bash
npm ci
docker compose up -d db
```

Загрузите переменные `.env` в окружение shell или через свой менеджер окружения. Для приложенного простого файла без пробелов и shell-символов можно использовать:

```bash
set -a
. ./.env
set +a
npm run migration:run --workspace apps/api
```

Создание демо-магазина выполняется только вручную в режиме разработки. Задайте `SEED_PASSWORD` в окружении; минимум 12 символов. Команда не переписывает пароли существующих аккаунтов.

```bash
ALLOW_DEMO_SEED=yes npm run seed --workspace apps/api
npm run dev --workspace apps/api
```

Демо-магазин: `11111111-1111-4111-8111-111111111111`. Аккаунты: `owner@example.test` и `cashier@example.test`; пароль — введённый вами `SEED_PASSWORD`. Не используйте демо-аккаунты в production.

## Запуск API в контейнере

```bash
docker compose up --build -d
```

API доступен на `http://localhost:3001`; база и API привязаны к localhost. Контейнер при запуске выполняет миграции, затем запускает сервер непривилегированным пользователем. Для нескольких production-реплик миграции нужно вынести в отдельный deployment job. Reverse proxy с HTTPS и секреты настраиваются отдельно.

Демо seed блокируется при `NODE_ENV=production`; создайте демо-аккаунты через локальную команду до переключения на контейнерный режим. Полноценная регистрация партнёров ещё не реализована.

## Проверки

Интеграционные тесты очищают только выделенную тестовую базу. Их запуск запрещён, если имя базы в `TEST_DATABASE_URL` не заканчивается на `_test`. Не указывайте рабочую базу или production-кластер.

```bash
docker compose exec db createdb -U mystore mystore_test
npm run format:check
npm run typecheck
npm run build
npm test
```

Тесты запускаются последовательно с настоящим PostgreSQL. В CI используются Node.js 24 и PostgreSQL 18; также собирается Docker image и проверяется HTTP-сценарий внутри контейнера. Локально первые 40 проверок выполнены на PostgreSQL 18.4. Тесты включают конкурентные продажи, повтор одинакового ключа и изоляцию магазинов.

## Сканер и интерфейсы

Обычный USB-сканер передаёт код в форму ноутбука как клавиатура с Enter. На текущем этапе API уже умеет искать товар по этому строковому коду, принимать приход и проводить продажу. Сам экран со сканированием, черновиками, печатью этикеток и подтверждением оплаты ещё не реализован. Реальное оборудование будет проверяться в следующем этапе.

## Ограничения первого этапа

Нет публичного каталога, фото, заказов, управления резервами, смен, денежных операций, оплаты, возвратов, модерации, UI, печати и фискальной интеграции. Поле reserved подготовлено для заказов, но API его изменения пока отсутствует. Этот API проводит внутреннюю товарную продажу; он не является готовой фискальной кассой и не подтверждает фактическую оплату.

Следующий этап — веб-интерфейс приёмки и кассы, смены и возвраты; затем печать, публичный каталог и онлайн-заказы. Уведомления и outbox подключаются вместе с внешними каналами; в первом этапе нет утверждения о синхронизации сайта.
